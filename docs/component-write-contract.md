# Approved SAM component writes

This path is qualified only for explicit `ort-webgpu` SAM analysis of a PNG source on the measured MacBook Air Mac17,3 / Apple M5 10-core GPU / 32 GB / macOS 27.0, using the app's ONNX Runtime 1.28.0 dylib with SHA-256 `dc19bbcb2f5c9fb3c68b4f9248aa0a35065ff702c5dbeae75eac54a74da97b6d`. The app runtime's built-in WebGPU path matched all 45 saved PyTorch MPS masks on identical Pillow-prepared input tensors. The app's PNG path was separately exercised on page 07. Every app inference requires both graphs to assign WebGPU nodes and zero CPU node events. Native CPU is review-only because page 27 differs by two threshold pixels. Other Macs, JPEG sources, and longstrips are not granted component-write authority. This is a mask parity and bounded-write qualification, not a human-label accuracy claim.

Each edit requires an explicit selected library chapter page, a selected `sam-xxxxx` component, a prepared support preview, and approval of its exact support SHA-256. Detector rectangles and COO polygons cannot grant pixels. The write mask is the versioned `MaskPlan` support derived from the immutable SAM component, optional add/remove corrections, and source-pixel round padding (default 0 px, supported range 0–64 px); the support version is `mask-plan-support-v1`. The PNG overlay uses luminance so zero pixels are transparent. A component keeps one stable `-hreview-sam-` region ID; later approved corrections and 2→5→2 padding revisions replace it with immutable patch sidecars that undo/redo can select exactly. Legacy Try again/Clean with cannot bypass this prepared-plan path.

Preparation checks the analysis backend and runtime SHA-256, measured host, current runtime file, library source SHA-256, decoded dimensions, PNG source format, paginated chapter mode, and that no other visible patch already writes within the selected support. The analysis and prepared plan pin `ort-webgpu`; the plan digest also includes the runtime SHA-256. It records the component support digest, SAM graph hashes/revision, the M1 bounded composited underlay digest, and the visible predecessor digest. Apply repeats the host/runtime/backend check, then checks source/support/underlay and region order under the chapter job lock and rejects stale identity or pixels. A neighboring prior edit is included in the composited input; a prior edit overlapping the raw-analysis support is refused. A revision of the same region reads the lower underlay without its own earlier patch. The patch is a bounded ring median fill, version `bounded-ring-median-v1`, and its mask equals the approved support exactly. It records all pinned identities and corrections in the versioned manifest and sidecars through `Job::complete_text_shape_region`.

Current scope is PNG sources in paginated chapters. The arbitrary-path analysis preview is of the original source, so a component whose pixels overlap another visible edit is refused. The UI previews the exact write permission raster; it does not preview the fill result. A later decision about JPEG must use the native decoded raster for the source preview and document that native decoding is canonical. Longstrip geometry requires separate qualification.

The native integration test `model_workflows::tests::exact_support_survives_manifest_export_and_persisted_undo_redo` decodes lossless exports before and after application, asserts every changed decoded pixel is in the approved component mask, checks stale predecessor rejection, and reopens the persisted undo journal before undo and redo. The UI test covers closed-gate review, destination selection, support preview, and explicit approval.
