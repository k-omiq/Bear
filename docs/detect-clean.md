# Detect, clean, and Text cleanup as separate steps

Status: contract for the implementation on `codex/cloud-integration`. The native side and the interface are built against this file; where the code has to differ, the code wins and this file is updated in the same change.

## 1. What changes for the user

Text cleanup used to be one step: find the text on a page and clean it at once, with nothing kept in between. It now has three steps, each on a page or a chapter:

| Step | What it does | Where it can run |
|---|---|---|
| Detect | Finds the text regions, fits their masks, and **stores** them as detected regions. Nothing is cleaned. | This computer, or the cloud GPU for the cloud-capable models (RT-DETR v2 full, SAM-TS-L), as `analysisTargets` says. |
| Clean | Cleans the stored detected regions. Nothing is detected again. | This computer (the automatic ladder, as today), or the cloud GPU (FLUX.2 Klein render), as `cleanTarget` says. |
| Detect and clean (Text cleanup) | Detect, then Clean. A page that already has detected regions is not detected again: its stored regions are cleaned. | Each half where its own setting says. |

A detected region is a real, stored region: it survives a reopen, shows on the canvas and in Layers, and can be deleted before cleaning. Detection done on the cloud is therefore used by every later clean, local or cloud, without sending the page again.

## 2. Stored detected regions (native)

`Project.detections: Vec<DetectedRegion>` (serde default, skipped when empty, so old manifests open unchanged):

| Field | Meaning |
|---|---|
| `id` | `{page}-d{n}`, `n` from a new `Counters.detections`. Stable across reopen. |
| `source_idx` | The page. |
| `bbox` | Page pixels (`Rect`). |
| `mask_ref` | Sidecar file holding the fitted mask the cleaner would use (the result of `fit::fit_within`), in page coordinates, same format as patch masks. It lives in a `detections/` subdirectory of the sidecar (`detections/{id}.mask`, with the fitted ink beside it as `detections/{id}.ink`), because a legacy patch writes `{id}.ink` at the sidecar root. |
| `inside` | Inside a detected balloon. |
| `balloon_color` | `Option<[u8; 3]>`, the balloon fill the run measured. |
| `script` | `Option<String>`, the script the gate read (`ja`, `zh`, `ko`). |
| `pick` | The rung the run would start this region at (`fill`, `solid`, `lama`): the effective start rung after the route and the ceiling, so passing it back as the pick reproduces the one-pass start. A `denoise` pick saved before that rung was removed reads as `fill`. |
| `detector` | `local` or `cloud` (cloud when any cloud stage contributed). |
| `created` | Seconds since the epoch. |
| `mask_sha256` | Hash of the stored mask file (serde default). |
| `order` | The region's position on the page, kept by the patch that replaces it (serde default). |
| `review_state` | `Option<String>`, `unusuallyLarge` when the run flagged it; carried to the patch (skipped when none). |
| `fit` | `Option<DetectionFit>`: `route`, `thickness`, `best_deviation` and the segmentation `scale` the fit ran at. A clean rebuilds the fit from the stored mask with these, so it matches the one-pass result without a detector (skipped when none). |
| `padding_px` | Total page pixels the stored mask and ink were grown past the SAM seed (or the last hand edit's baseline), from the Mask padding control (serde default 0, skipped when 0). Above 0 the ungrown pair is kept beside them as `{stem}.base.mask` and `{stem}.base.ink` (`DetectedRegion::base_mask_ref`), and a padded record written without that pair is refused. |

Rules:

- Only regions the gate would clean become detections. Gate-skipped and language-skipped regions stay `regions_untouched` rows, as today.
- A region is one text group (`cleaner_core::text_groups`). The lettering mask (SAM-TS-L when selected) decides what is lettering, and the Ogkalu boxes say whether it is inside a balloon (`text_bubble`) or outside (`text_free`). Lettering no box claimed is still a region, outside unless a balloon holds it, so the outside-text choice and the gate decide it. Its group record keeps the reason (`unassignedComponent`); that is provenance, not a `review_state`. Lettering within reach of other lettering in the same balloon (one larger glyph, at most 96 px) is one region, so an effect the boxes cut in pieces is cleaned as one crop. A join never makes a region larger than 900 px on a side (the long-strip detection overlap), and a `text_bubble` box with no balloon box around it joins nothing, because inside or outside is read at the region's centre. The region's mask is the lettering's own pixels plus the fit's halo, never the reach. Outside a balloon the lettering is first grown by half its stroke width (at most 8 proxy px, `fit::outlined`), because a lettering mask leaves out the outline an effect draws around its letters, and the art around it stops the fit's own growth a pixel or two past the letters.
- Detect on a page drops that page's old detections and old untouched rows first, and keeps its patches. A new detection whose area lies at least half inside an existing patch's box is not stored (it was cleaned already).
- A detection that is cleaned is removed, and its patch or untouched row takes its place in the same write. The patch keeps the detection's id (`{page}-d{n}`) and order.
- `ApiRegion.outcome` gains `"detected"`; such a region carries its `mask`, `source: "auto"`, `detected: true`. `ApiPage.status` gains `"detected"` for a page that has any detection. The detected region's mask is `{id}-m1`. `region_count` counts detections; `done_count` does not.
- Mask padding (`run_clean`'s `maskPaddingPx`, 0 to `MAX_MASK_PADDING` = 32, `mask_padding_invalid` past it) grows both mask and ink directly from the SAM seed by that total radius inside the fit's window; 0 keeps the seed exactly, and neither automatic fitting, outside-text outlining nor model-hole padding is added to the stored base. Detect stores that result, and a one-pass run cleans through it. It is written into the run snapshot (`runMaskPadding`), so a resumed run pads as the interrupted one did.
- Deleting a detected region removes it and its mask files (it has no pixels to restore). It arrives through `deleteMask` on its mask, or `restoreRegion` with no region; neither can bring it back.

## 3. Commands

### `run_clean` gains `mode`

`mode: "auto" | "detect" | "clean"`, default `"auto"`, the last argument; any other value is refused. All other arguments, events (`page-started`, `region-done`, `page-done`, `run-finished`, `notice`), the run slot and `cancel_run` are unchanged. The mode is written into the run snapshot (`runMode`), so an interrupted run resumes in its own mode. `apply_tool`'s autoClean branch accepts the same `mode` in its params.

- `detect`: detection only, per section 2. Cloud detection needs the run grant exactly as today (`proposeRunAnalysis` / `confirmRunAnalysis`, then `cloudGrant`). A page is not marked examined by Detect. A stored detection sends no `region-done`; the run ends with notice `notice.run.detected` (`{ pages, regions }`) when it detected regions and cleaned none.
  The proposal and grant bind each page index to its source index and SHA-256 hash. A changed page fails with `cloud_run_source_changed` before its first tile, and the run treats it as a page failure. Selection and profile epoch are checked again before every tile send.
- `clean`: cleans stored detections on this computer with the automatic ladder (`HIGHEST_AUTOMATIC` still caps it), starting each at the run's own picks (`bubbleEngine` for a region inside a balloon, `outsideEngine` for the rest) when the run names them, as Text cleanup always does, and at its stored `pick` otherwise. No detector model loads. A `solid` pick fills with the detection's stored `balloon_color`, and with the run's `bubbleColor` only when none was measured (a detection outside a balloon): the interface always sends a colour, white by default, so the setting first would paint every grey balloon white. Pages without detections are skipped; if none in scope has any, the run starts nothing and sends notice `notice.run.nothingDetected`. A `cloudGrant` with `clean` is refused (`cloud_run_grant_mismatch: capabilities`), since nothing is sent.
- `auto`: a page with detections is cleaned as `clean`; any other runnable page is detected and cleaned in one pass, as today. That one pass does not clean a region whose area lies at least half inside a patch the page already held before the pass (a cleaned detection or a hand edit, a deleted one included), the same test Detect applies; such a page is one whose detections were cleaned or deleted and that was never examined.

### `run_clean` on one area

`area: { x, y, w, h }`, in percent of the page as it is shown (what a region's `bbox` is), holds a `detect` of one page to that area. It is for text the page's Detect missed, and for a mask that was deleted. Any other mode or scope is refused (`detect_area_scope_unsupported`), and an area that is not on the page is refused (`detect_area_invalid`).

- The models read a window around the area and nothing else of the page: the area grown about its middle to 1024 px on each axis (the detectors' input side, and one cloud tile), moved back inside the page (`DetectArea::window` in `src-tauri/src/run.rs`). A whole page is scaled down to that side, which is how small lettering is missed; the window is read at the page's own resolution. A cloud stage sends the page as a page Detect does, on the same consent, and its answer is cut to the window.
- Grouping, the gate, the fit and the padding run as in a page Detect. A row is kept when its box touches the area; the rest of the window is context.
- What is found is added to what the page holds (`Job::add_area_detection_results`): no detection, patch or untouched row is replaced or moved. A detection whose box lies at least half inside a patch is left out (the page Detect's own test). Every other one is cut to what the page does not hold, by pixel (`area_detection_less_held` in `src-tauri/src/region.rs`): each stored detection's display set, grown by 4 px, is taken from its mask, its lettering and its ungrown pair, a run of fewer than 64 connected pixels left touching that cut is dropped as a sliver, and the detection is left out when fewer than 64 pixels remain. By pixel and not by box, because the window groups text by what it sees: on the user's scan 19 a deleted balloon came back joined to the outside text under it, which the page still held. A detection cut this way keeps its fit and pick and loses its group record, and keeps the inside or outside answer of the region it was found as. An untouched row has no pixels, so it is left out when its box lies at least half inside a row or detection the page holds, or holds one at least half. The detections kept take orders after everything on the page.
- The page is not recorded in `detected` and is not marked examined: an area is not the page. The page is always in the queue for it, cleaned or detected before or not.
- The area is written into the run snapshot (`runArea`, null for every other run), so an interrupted run resumes held to it. As a page Detect it would replace every detection the page holds.
- The run ends with `notice.run.detected` when it stored a detection, and with `notice.run.nothingNewHere` when it stored none.

### `apply_tool` on a detected region

Given a `{page}-d{n}` region id, `apply_tool` cleans that one region from its stored mask (no re-detection), locally, as for any region, starting at its stored `pick` unless the call names an engine, a fill mode or a box. The detection is replaced by the result in one write.

- The interface's Clean (Layers row and region menu) sends `tool: "autoClean"` with the region id and only `bubbleColor` in its params, so the stored `pick` decides the rung. The answer is the ordinary `applied` result.
- The interface records no undo for this clean or for deleting a detection, since undo would have to put a detection back. A cleaned detection is undone by deleting its patch.

### Editing a detection's mask

What a detection may erase is its **display set**, `mask ∪ ink`: fill and solid write through `mask`, and the model rungs (LaMa here, FLUX on the cloud) write through `ink` grown by the isolation radius, with `ink` as the cloud render's hole. On the user's library 3.7% of ink pixels lay outside the mask, so neither file alone is the area. The model rungs' isolation ring (5 px past `ink`, locally and in the cloud) reaches past it: on two of the user's chapters 17% to 22% of what LaMa wrote lay outside the display set. So `Job::complete_detection`, which every clean of a detection commits through, cuts the patch's coverage and lettering back to the display set and recomputes its mask digest. Nothing outside the drawn mask is written, on any rung. The model still reads the page around it as context.

`edit_detection_mask({ chapterId, pageIndex, expectedSourceIdx?, expectedSourceSha?, mode, stroke?, painted? })` (`src-tauri/src/region.rs`) edits the detections of one page. `stroke` is a brush path (`{points, radius}`, as `create_region` takes it) and `painted` an area (`{kind: "rect"|"ellipse"|"polygon", points, feather}`); a non-null `stroke` is used alone. The gesture S is rasterised at page resolution and clipped to the page, so a longstrip gesture stops at its own page's edge.

- `add`: the detection whose display set S overlaps most takes S, less every pixel another detection's display set holds (ties: lower `order`, then id). Its mask becomes `display ∪ S`, its ink `ink ∪ S`. Over no detection, S becomes a new detection (`inside: false`, `pick: "lama"`, `detector: "local"`, no fit, no group, `order` after the page's detections and patches). An add that brings no new pixel writes nothing.
- `remove`: every detection whose display set S touches loses S from both files (its mask becomes `display \ S`). A detection left with no mask is removed; one left with mask but no ink takes the mask as its ink.
- Masks are stored cropped to their tight bounds, the record's `bbox` becomes the mask's bounds, and `ink ⊆ mask` holds after any edit. `fit`, `group`, `pick`, `inside`, `balloon_color`, `order` and `review_state` are kept.
- One manifest write (`Job::rewrite_page_detections`): ids are kept, the masks go to fresh files (`detections/{id}.e{n}.mask` and `.ink`), and superseded files are deleted after the flush. It takes the chapter lock, so a run holding the chapter refuses it.
- Answer: `{ pageStatus, changed, created, removed }` (ids), or `null` for a missing chapter or page, a source mismatch, or a gesture that covers nothing. `mask_edit_mode_invalid` for any other mode. A cloud clean plan bound before an edit skips the edited regions as changed.
- No undo, for the reason deleting a detection has none.

### Changing a detection's padding

`set_detection_padding({ chapterId, pageIndex?, regionId?, paddingPx })` (`src-tauri/src/region.rs`) re-pads every detection on one page, or on every page of the chapter when `pageIndex` is `null`, whose `padding_px` differs (or whose untouched legacy baseline can be recovered from saved group evidence): mask and ink become the ungrown pair dilated by `paddingPx`, clamped to the page, and `padding_px` takes the new value. It always grows from the ungrown pair, so any sequence of paddings ends where the last one alone would, and 0 writes the ungrown pair back as the masks and drops the `.base` files. `bbox`, `group`, `pick` and routing are kept; the recorded thickness follows the total padding for seed-based masks. `padding_from_seed` marks that baseline (serde default false for legacy records). Apply can recover an untouched legacy mask from verified group evidence, even when the requested numeric padding is unchanged. Legacy masks already revised or lacking group evidence retain their stored baseline to preserve hand edits; re-detect those to obtain a SAM baseline. Each page is one `Job::rewrite_page_detections` write under fresh `e{n}` files, under the chapter lock. Answer: `{ changed, removed, pages }` (the detection ids rewritten, the ids a merge took off the page, and page indices), or `null` for a missing chapter; `mask_padding_invalid` past 32.

Each expanded detected-mask row in Layers also has a Mask padding slider. It reads the detection's saved `paddingPx` and writes on release (or a keyboard change), passing `regionId` to update only that detection. Invalid or out-of-scope targets are rejected with `mask_padding_target_invalid` before any writes. The control is disabled while saving or running, and the page reload refreshes its mask overlay. Cleaned layers do not offer this control.

**Padding that runs detections together makes them one.** Two detections are merged when their display sets overlap anywhere or their nearest pixels are within 4 page pixels (`MERGE_REACH`, `run_together` in `src-tauri/src/region.rs`), and at least one of the two is padded. Unpadded detections that touch stay two, because that is how Detect grouped them, and a padding of 0 merges nothing. Reaching is carried along: a first that reaches a second that reaches a third makes one of the three. The detection earliest in reading order keeps its id and its order (`made_one`). Its mask, lettering and ungrown pair become every member's together, so a later padding grows from all the letters; `padding_px` is the widest any member had, and `bbox` spans the members' boxes. `inside` holds only when every member was inside a balloon; `balloon_color`, `script` and `pick` are kept only when every member had the same, and a pick they disagree on, or a `fill` or `solid` across the edge of a balloon, becomes `lama`. `fit` and `group` are dropped, as for a hand mask. The other members leave the page with their files and are answered in `removed`. A merge is not undone: a smaller padding, 0 included, shrinks the one detection, and Detect on the page again is the way back to two.

What may start a merge is the call's scope. A page or chapter call merges across every detection of each page, including pairs that already had the padding asked for. A call with `regionId` merges only what that one detection now reaches, and the row named can be the one that leaves when the detection it reached is earlier in reading order. The interface says how many masks were merged (`notice.mask.paddingMerged`) and reads the page again.

Detect merges the same way before it stores a page (`merged_by_padding`, called from the page walk in `src-tauri/src/run.rs`), so a Detect with padding and a padding applied afterwards leave the same detections. A Detect of one area merges among what it found only: what it found was already cut 4 px clear of what the page holds.

A hand edit of a padded detection (`edit_detection_mask`) applies the same change to its ungrown pair: what the edit added to the display set is added to it, and what it took away is taken from it, so an add outlives a later padding and an erase near the letters can grow back by the padding, as it would after Detect. An edit that leaves the ungrown mask empty makes the edited masks the new ungrown pair, with `padding_px` 0.

The canvas draws each detection from `tile://localhost/<chapterId>/<pageIndex>/detection/<regionId>?v=<maskSha256>.<sequence>` (`src-tauri/src/tile.rs`): a PNG of the display set cropped to its tight bounds, opaque white inside and transparent outside, with `x-mask-bounds: x,y,w,h` (page pixels, exposed to the page) and `Cache-Control: no-store`. `sequence` in `v` is the region's mask `sequence`, one more than its hand edits (the `n` of `detections/{id}.e{n}.mask`), because an edit can change the lettering and leave the mask file's digest as it was. The interface caches by URL, so an edit fetches again exactly the detections it changed.

### Cloud clean (batch, with consent)

The cloud is reached only through these calls. No page data is sent before `start_cloud_clean`; `prepare_cloud_clean` reads only the gateway's model identity (`GET /mc/v1/model`) and GPU price (`GET /mc/v1/gpu`), and writes nothing but the picks Text cleanup sends (below). One consent covers the whole plan; the run sends it in bounded chunks. The code is `src-tauri/src/inference/cloud_clean.rs`.

1. `prepare_cloud_clean({ chapterId, scope: "page"|"chapter"|"regions", pageIndices?, regionIds?, localFirst = false, bubbleEngine?, outsideEngine? })`
   - Describes the work and does none of it: nothing is cleaned or sent.
   - Collects the stored detections in scope, in page order and then reading order: the pages in `pageIndices` (one or more) for `page`, every detection of the chapter for `chapter`, the listed ids for `regions`.
   - Each of `bubbleEngine` and `outsideEngine` that is given (Text cleanup sends both) is saved as the `pick` of every region in scope on its side of a balloon first, through the route and the ceiling as detection does, and the plan reads the new picks. A pick decides only what the mixed choice tries here first: every region is sent otherwise, one set to LaMa included, and none is cleaned by LaMa on this computer. A side not given keeps each region's saved pick. This is the one write prepare makes. A Layers row and the region menu send neither, except under the mixed choice (below), when they send a `fill` or `solid` bubble pick alone. Regions left out as unresolved (below) keep theirs.
   - Leaves out every region whose earlier cloud request is unresolved (an `Unknown` attempt, one accepted and not finished, or one pending attachment, as the attempt journal's `unresolved_region_attempt` reads them): a second request could render and bill it twice. Those ids are returned in `unresolvedIds`; recover them first.
   - `localFirst` is the explicit **mixed** execution choice, off by default. Off (`execution: "cloud"`), every region in the plan is cleaned on the cloud GPU and none on this computer. On (`execution: "mixed"`), nothing changes at prepare; after `start_cloud_clean`, just before each chunk goes to the cloud, each of its detections whose `pick` is `fill` or `solid` is first tried on this computer at rung 0 alone, a page at a time; a result the quality metric accepts is committed as an ordinary local patch, and only the rest are sent. `localCandidates` counts those picks. The consent, the GPU time and the cost range still count every region as sent, so the user agrees to pay up to that full amount and mixed only ever sends less. The interface asks for it from the Text cleanup panel's checkbox (§5), which a Layers row and the region menu also read.
   - Refused (the string is the error): `cloud_disabled`; `cloud_clean_profile_not_active` (no cloud profile selected, or it is unusable); `credential_missing`; `endpoint_invalid`; `cloud_clean_run_active` (a run holds the slot); `cloud_clean_scope_unsupported` (any other scope, `project` included); `cloud_clean_no_pages` / `cloud_clean_page_not_found`; `cloud_clean_no_regions` / `cloud_clean_region_not_found` (an id that is not a stored detection); `cloud_clean_too_many_regions` (a plan above 16,384 regions, 16 chunks of the 1024 one chunk may carry, checked before anything is read or asked); `cloud_clean_proposal_limit` (16 open proposals, checked before the gateway is asked); a gateway code from the model read (`gateway_unauthorized`, `gateway_unreachable`, `gateway_error`, `gateway_protocol`, and the others `get_cloud_gpu_status` uses).
   - Returns `{ proposalId, chapterId, regionIds, regions, pages, pageIndices, totalCropPixels, totalWorkPixels, localCleaned, execution, localCandidates, chunkRegions, chunks, unresolvedIds, estimatedGpuSeconds: { low, high } | null, estimatedCostUsd: { low, high } | null, gpu, provider, profileName, planDigest, expiresAtMs }`. `regionIds` is the plan, in the order the run takes it. `pages` is the number of pages, `pageIndices` the pages. `totalCropPixels` sums each region's crop as its stored mask's box sizes it (the render refits the mask, which can move a crop by one stride); `totalWorkPixels` sums the size the worker edits each crop at. `chunkRegions` (256) is the chunking rule and `chunks` the number of chunks. `localCleaned` is always 0 (kept for older readers). `gpu` is the deployment's GPU as the gateway names it. `planDigest` is the SHA-256 the consent binds (below). With nothing to send it returns `regions: 0`, `proposalId: null`, `planDigest: null` and `expiresAtMs: 0`, and asks the gateway nothing.
2. `confirm_cloud_clean({ proposalId, planDigest, rightsAttested, retentionAcknowledged })` returns `{ grantId, expiresAtMs }`. `planDigest` is the plan the consent dialog showed, and the grant is minted only when it is the proposal's own: consent binds the plan, not only the proposal id. Refused with `rights_attestation_required` or `retention_acknowledgement_required` (the proposal stays open), `cloud_clean_proposal_missing`, `cloud_clean_proposal_expired`, `cloud_clean_plan_mismatch` (another plan's digest, or none; the proposal is spent), `cloud_clean_grant_limit` (16 live grants), `cloud_clean_profile_changed`, `cloud_disabled`. The grant is single use, valid for 120 s, and holds that plan. The plan digest is SHA-256 over the domain `cloud_clean_plan_v1` and the chapter, the provider, profile and endpoint fingerprint, the recipe, the execution, the chunking rule, the ordered regions (each id, page, revision hash of source, record, mask and lettering, and text group id) and the estimate in integer units (crop and work pixels, GPU milliseconds, cost in micro-dollars, the GPU and its price). It is also bound to the profile epoch.
3. `start_cloud_clean({ grantId })` starts a run in the ordinary run slot and returns its handle like `run_clean` (`{ runId, pages }`, or `{ runId, pages: [], alreadyRunning: true }` without spending the grant when another run holds the slot). It re-reads the recipe from the gateway and spends the grant; refused with `cloud_clean_grant_missing` (unknown, or already presented once, matched or not), `cloud_clean_grant_expired`, `cloud_clean_grant_mismatch: profile`, `cloud_clean_grant_mismatch: endpoint`, `cloud_clean_grant_mismatch: recipe`, `cloud_clean_profile_changed`, and the selection codes above. It emits the ordinary run events and is cancelled with `cancel_run`.
   - In mixed execution only, each chunk's local flat-colour pass runs after that chunk's check and before its grant, one page per call: the chapter is held for one page at a time, and a cancel is heard before the next page. What a call committed is read back from the chapter (without the job lock, as a read), so a page whose pass failed partway still settles the regions it saved, with their `region-done`, and does not send them.
   - Chunks: the plan is cut into consecutive chunks of at most 256 regions (never more than the 1024 one chunk may carry). Before each chunk the run checks its authority again: cloud engines still allowed and the profile still selected, the profile epoch unchanged (an edited key or endpoint moves it), and the deployment's recipe and GPU with its list price still those the estimate priced. The price is read as prepare reads it: a price not stated or not readable is no price. A plan priced at prepare stops when the price now differs or cannot be read; a plan consented to with the cost unknown claimed no GPU and is not held to one. Any change stops the plan with `notice.cloudClean.stopped` (`cloud_run_profile_changed`, `cloud_clean_recipe_changed`, `cloud_clean_gpu_changed`, or the allowed check's own code), and no later chunk starts. It then mints the chunk's grant from the plan's own list, leaving out regions already done and any region whose cloud request has become unresolved since (skipped with reason `unresolved`), and verifies the grant is a subsequence of that chunk's range of the approved list before one region starts; an id outside it refuses the chunk (`cloud_clean_chunk_outside_plan`, `cloud_clean_chunk_mismatch`) and stops the plan. A cancel stops the chunk in flight and every chunk after it.
   - Per region: re-read it from disk and compare its revision hash with the bound one (a region edited or deleted since consent is skipped, never sent), build the crop from the stored mask, mint and spend a per-region grant, and render through the one cloud render path (journal, recovery, `cloud://attempt` phases).
   - Up to 3 renders in flight. A region waits while a region below it on the same page and within the underlay read margin (768 px plus the widest crop context) is still to be committed, because its input is composited over that patch and the attach refuses a result whose underlay changed. So regions of one page go one after another, and the three slots are spent on different pages.
   - Each result replaces its detection with a patch in one write, as it arrives. The patch keeps the detection's id, order and review state; it is recorded as engine `flux` with `execution_provider: "cloud"` and a `provenance.cloud` record (the interface already reads `provenance.cloud` as a cloud patch), `params_snapshot.source: "auto"`, and, when the detection had one, its text group record in `params_snapshot.group`, so source mask, logical group, request and output stay traceable.
   - Events: `page-started` when a page's first region starts, `region-done` for each committed region, `page-done` when a page's last region ends (a page left unfinished by a cancel or stop still gets its `page-done`), and one `run-finished` (`reason` `completed` or `cancelled`; `nextPageIndex` on cancel is the first page with a region still detected). The closing notice is the run's usual one (`notice.run.finished`, `notice.run.cancelled`, `notice.run.pagesFailed`, `notice.chapter.emptyResult`).
   - A region that fails stays detected, with notice `notice.cloudClean.regionFailed` (`{ regionId, page, code }`, `page` 1-based, `code` the render's stable code such as `remote_failed`, `poll_timeout`, `submission_unknown`, `gateway_unreachable`). It is not retried and not cleaned locally instead. A skipped region sends `notice.cloudClean.regionSkipped` (`{ regionId, page, reason: "changed" | "gone" | "unresolved" }`).
   - A failure that withdraws the run's authority (`cloud_disabled`, `gateway_unauthorized`, `credential_missing`, `cloud_run_profile_changed`: an edited or deleted profile, or another profile selected) stops the run: nothing more starts, the renders in flight are cancelled, and `notice.cloudClean.stopped` (`{ page, code }`) is sent once.
   - After the last chunk, or a stop over a changed deployment or a refused chunk, when anything was sent and the run still speaks for the endpoint (no stop withdrew its authority), the app asks once for an idle-only release of the `render` GPU (`POST /mc/v1/gpu/stop` with `idle_only`), and ignores any failure. The gateway sends it only when no render job is pending or running (docs/cloud-api.md).
   - `cancel_cloud_clean({ proposalId })` drops an unconfirmed proposal; `true` when there was one.

Estimate: each region is its own job, sized from its own crop. The crop is the one the render builds from the stored mask's box; the worker upscales it so its long side is 768 and snaps both sides down to the latent stride of 16, never downscaling (`working_size` in deploy/cloud/common/flux.py). A job takes `2 s + 10 s per working megapixel`. `estimatedGpuSeconds.low` is the sum over jobs; `high` adds `cold_start` (55 s) and the idle window (600 s, the maximum deployment idle setting, because the deployed setting is not available before a container starts; see docs/findings.md). `estimatedCostUsd` prices both bounds per second at the endpoint's GPU list price plus the worker's CPU (2 cores) and memory (12 GiB, 24 GiB for a 9B model, 32 GiB for Qwen-Image-Edit-2511) at Modal's published rates, and is `null` when the gateway states no price. The per-job overhead, the per-megapixel rate and `cold_start` are unmeasured constants for Klein. A Qwen-Image-Edit-2511 deployment edits every crop at about one megapixel on a 32 px grid whatever its size, at 7 s per working megapixel and a 90 s cold start (`RenderRate` in src-tauri/src/inference/cloud_clean.rs); the 7 s is measured warm on an L40S, the cold start is not.

### Settings

`cleanTarget: "local" | "cloud"`, default `"local"`, strict like `analysisTargets` (any other value is refused by the settings writer). The backend acts on no setting here: a cloud clean starts only from the calls above.

## 4. Text cleanup with the cloud

The interface runs the steps in order and asks before each spend:

1. Detection consent, only when a detection stage is on the cloud (today's run consent dialog).
2. `run_clean` with `mode: "auto"` when `cleanTarget` is local. When `cleanTarget` is cloud: `run_clean` with `mode: "detect"`, then on `run-finished`, `prepare_cloud_clean` for the same pages with `localFirst: false` (or `true` only when the Text cleanup panel's "Clean flat colours on this computer first" checkbox, `toolParams.autoClean.localFirst`, is ticked), then the cloud clean consent dialog (exact region count, batches and cost, once for the whole plan), then `start_cloud_clean`. When the detection consent comes first, it says that cleaning asks separately once detection has finished.

Declining the cloud clean consent leaves the regions detected; nothing is lost.

A project-wide scope stays local only. A long strip runs on the cloud like a paginated chapter. Each page is sent once, and a detect window that reaches across a verified join reads the next page's answer, so a box cut by the join is merged. The cloud clean treats the whole strip as one space, so a region waits for any earlier region within reach, across a join too.

A cloud clean from a Layers row or the region menu is `prepare_cloud_clean` with `scope: "regions"`, that one id and `localFirst` from the same checkbox, then the same consent. With the checkbox ticked and Text cleanup's bubble pick Fill or Solid, it also sends that pick as `bubbleEngine` alone, so a region inside a balloon is tried here first and one outside keeps its saved pick. A detect run that was cancelled asks nothing; when the chapter changed before the run finished, nothing is prepared and the regions stay detected, with a notice.

## 5. Interface

- The Text cleanup tool has a **Mode** choice (Detect, Clean, Detect and clean; default Detect and clean), a **Detect on** choice (This computer, Cloud GPU; sets both cloud-capable stages of `analysisTargets`, disabled with the reason when the cloud cannot take them), and a **Clean on** choice (This computer, Cloud GPU; sets `cleanTarget`). The run buttons name the step (for example "Detect chapter", "Clean page"). Text cleanup opens as a compact panel rather than a pill, with one labelled row per run choice (Mode, Detect on, Clean on and the text choices), so each choice is one press from the button it decides.
- Detected regions draw on the canvas as their masks, the display set of §3, filled at the selection opacity and outlined in the selection colour of their kind (Settings > General: `session.maskColor` default `#0284c7` for text inside a speech bubble and for regions whose place is unknown, `session.outsideMaskColor` default `#c2410c` for text outside a bubble, and `session.maskOpacity` default 35, kept in the browser's storage). No box is drawn; the region's button stays for hover, selection, the menu and the keyboard. A lit region's outline thickens and its fill strengthens. Outside the app (the mock) the box stands in, in the same colours. They show as **Detected** rows in Layers, with actions Clean, Clean on cloud (when the cloud is usable) and Delete.
- A detected region's right-click menu has a **Text type** section between Clean with and Delete, Speech bubble text or Text outside bubbles with the current one checked (neither for a row stored before `inside` existed), and picking the other sends `set_detection_type` (`src-tauri/src/library.rs`), which sets `inside`, clears `balloon_color`, turns a `fill` or `solid` pick into `lama` when the region moves outside a balloon, and has no undo, like a mask edit.
- The **Selection** tool (`maskSelect`, key `6`) edits those masks: **Add** or **Remove**, with a **Brush** (size 4 to 160 px), a **Lasso** or a **Rect**. It sends `edit_detection_mask` and reloads the page. Add previews in the colour of the detection it joins, or in the outside colour over empty paper, since a new hand area is stored as outside text; Remove previews as dashes over a dark line, or a hatched stroke.
- With the Selection tool, a right-click over bare paper opens a menu with **Detect text here**. It starts a `detect` of that page held to a box around the pointer, 16% of the page's width on a side (`gesture.js#detectAreaAround`), where Text cleanup detects, and finds all text there as Detect on its own does (`textPolicy: all_text`, outside text included). A right-click over a region keeps the region's own menu. The entry is disabled while a run is active, and the keyboard's menu key does not offer it, because it names no spot on the page.
- The Pages list marks a page that has detected regions waiting.
- While Clean on is Cloud GPU, the panel shows a **Clean flat colours on this computer first** checkbox (`toolParams.autoClean.localFirst`, off by default, with a hint under it). Ticked, the run's cloud clean, and a Layers row's or the region menu's, asks for mixed execution; unticked, every region goes to the cloud GPU.
- The cloud clean consent dialog shows the region count, the pages, where they are cleaned (the cloud GPU only, or the mixed choice, how many flat-colour regions it tries here after the start, and that the GPU time and cost range still count every region as sent), the batches and that the one consent covers them all, any region held back by an unresolved request, the GPU time and cost range, the GPU, the endpoint and the plan fingerprint, and asks the same two statements as the other cloud consents. Confirm answers with the plan fingerprint shown, which `confirm_cloud_clean` checks.
  - The endpoint shown is the selected profile's address as the readiness check read it just before `prepare_cloud_clean`; the proposal carries no URL.
- Settings > Detection has the same **Clean on** choice, bound to `cleanTarget`.
- Each refusal code of the three cloud clean commands reads as a plain notice (`editor/cloudrun.js#cloudCleanErrorKey`); an unknown code reads as the step that failed. `job_busy` (another Manga Cleaner process holds the chapter while it is prepared) reads as `notice.job.busy`. `alreadyRunning` from `start_cloud_clean` is said as a busy slot, and the regions stay detected.
- The batch's notices name their cause in words where the catalogue has them (`model/cloudnotices.js`); an unknown `code` is left out of the sentence rather than shown.
