# Manga Cleaner Rung 3a Sidecar - the `sdnq` backend (torch + diffusers).
#
# The **portable** arm: CUDA, Intel XPU or Metal, so Windows, Linux and macOS.
# Separate from requirements.txt on purpose - that file is `mflux`, which is MLX,
# which installs only on Apple Silicon, and a single file would make one platform
# unable to install either backend. A virtual environment may hold this file, the
# other one, or both; the sidecar reports which backends it can import on
# `GET /v1/health` and the application refuses a backend that is not there
# (`decline.reason.sidecarBackend`).
#
# Floors, not pins. Every version below is the floor a *working* installation was
# measured at (the versions in brackets), taken from the reference
# implementation's environment plus this repository's own:
#
#   torch 2.13.0 · torchvision 0.28.0 · diffusers 0.42.0 · sdnq 0.2.8
#   transformers 5.15.0 · accelerate 1.14.0 · safetensors 0.8.0
#   huggingface-hub 1.33.0 · peft 0.21.1
#
# Four of the floors are load-bearing rather than conservative:
#   * diffusers >= 0.42 and sdnq >= 0.2.8 are what FLUX 3's modular pipeline needs.
#   * transformers >= 5.0 is where `Qwen3ForCausalLM` - Klein's text encoder,
#     named in the checkpoint's own model_index.json - exists.
#   * peft is what keeps Qwen's Lightning and FukidashiErase LoRAs as adapters.
#   * torchvision is what FLUX 3's `Qwen3VLProcessor` needs. It has to match torch,
#     so a torch installed first from another index brings its own (`bootstrap.py`).
#
# **The torch wheel is the platform's, and pip's default may be the wrong one.**
# On Linux with an NVIDIA GPU, install torch from the CUDA index *first*; the
# default PyPI wheel there is CPU-only, and this backend refuses a machine with
# no accelerator rather than running a 4B transformer on a CPU. See
# sidecar/README.md §2.
